래치에서 눈여겨볼 장면은 입력을 켜는 순간보다 **다시 끄는 순간**이다. Set을 잠깐 켰다가 꺼도 출력은 1에 머문다. 입력은 사라졌는데 상태는 남는다.

이번 글에서는 NOR 게이트 두 개를 연결한 SR 래치를 작은 실험으로 정리한다. 보안 쪽으로 가져가면 질문이 조금 달라진다. 이 1비트가 잠금 상태라면, 누가 바꿀 수 있고 언제 지워져야 할까?

<!--more-->

*블로그의 글 형식과 인터랙션을 시험하는 예시 기록이다. 아래 실험은 브라우저의 논리 모델이며, 실제 장비에서 수행한 측정이나 취약점 발견 기록은 아니다.*

## 먼저, 1을 남겨보기

아래에서 **Set → 유지** 순서로 눌러보자. 입력 S와 R은 모두 0으로 돌아가지만 Q는 1이다. 이어서 **Reset → 유지**를 누르면 같은 입력 조합에서 Q가 0으로 남는다.

{% include posts/latch-lab.html %}

입력 `00`만 찍은 사진으로는 Q의 값을 알 수 없다. 그 전에 어떤 입력을 줬는지까지 알아야 한다. 조합회로의 진리표를 읽던 방식에서 한 발 더 나아가는 지점이다.

## 되돌아오는 선이 기억을 만든다

이 글은 **입력이 1일 때 동작하는 NOR형 SR 래치**를 기준으로 한다. S는 Set, R은 Reset이다. 각 출력은 다른 NOR 게이트의 입력으로 돌아간다.

```text
Q     = NOT (R OR Q_bar)
Q_bar = NOT (S OR Q)
```

S=1, R=0이면 Q는 1이 된다. 두 입력을 0으로 돌려도 Q=1이 반대편 출력을 0으로 유지하고, 그 0이 다시 Q=1을 지탱한다. 전원이 유지되고 다른 유효한 입력이 들어오지 않는 동안 이 관계가 이어진다.

| S | R | 안정된 뒤의 Q | 의미 |
| :--: | :--: | :--: | :-- |
| 0 | 0 | 이전 값 | 유지 |
| 1 | 0 | 1 | Set |
| 0 | 1 | 0 | Reset |
| 1 | 1 | 0, Q_bar도 0 | 금지 입력 |

여기서 `Q_bar`라는 이름은 주의해서 읽어야 한다. 정상적인 두 안정 상태에서는 Q의 반대지만, 모든 입력에서 항상 반대인 것은 아니다. [University of Vermont의 래치 강의](https://www.uvm.edu/~cbcafier/cs2210/content/04_logic_gates/latch_and_flip_flop.html)에서 회로식과 상태 전이를 확인할 수 있다.

## 두 입력을 같이 켰다가 끄면

실험에서 **금지 입력 → 유지**를 눌러보자. 출력이 `?`로 바뀐다.

S=R=1인 동안에는 두 NOR 출력이 모두 0으로 강제된다. 문제는 두 입력을 함께 0으로 되돌릴 때다. 실제 회로에서는 전파 지연과 소자 차이 등이 결과에 영향을 준다. 이 모델은 그 뒤의 값을 임의로 골라 보여주는 대신, **이전 상태를 확정할 수 없음**으로 표시한다. 아날로그 전압이나 준안정성의 지속 시간을 재현하는 시뮬레이터는 아니다.

다시 Set이나 Reset을 주면 알려진 상태로 돌아온다. 또한 금지 입력에서 한 입력만 먼저 내리면, 남아 있는 유효 입력이 상태를 정할 수 있다. 그래서 입력의 값뿐 아니라 **입력이 바뀌는 순서**도 기록해야 한다.

초깃값에도 같은 주의가 필요하다. 이 실험은 시작 전에 Reset을 가한 상태를 가정한다. 실제 래치가 전원을 켜자마자 자동으로 0이 된다는 뜻은 아니다.

## 보안에서 다시 보게 되는 1비트

회로의 Q를 `locked`라는 이름으로 읽어보면, 검토할 질문이 생긴다. 잠금을 설정한 뒤 일반 소프트웨어가 다시 지울 수 있는가? 초기화 경로에서도 설계한 접근 정책이 유지되는가?

MITRE의 [CWE-1231](https://cwe.mitre.org/data/definitions/1231.html)은 접근 제한에 사용하는 잠금 비트가 설정된 뒤에도 변경될 수 있는 문제를 다룬다. 잠금 비트를 저장했다는 사실만으로 보호가 완성되지는 않는다. 그 비트에 도달하는 쓰기 경로와 상태 전이도 검토 대상이다.

다만 위 SR 래치의 금지 입력이 곧 CWE-1231이라는 뜻은 아니다. 기본 기억 소자의 동작과 시스템의 접근 제어 결함은 구분해야 한다. 실제 제품에서 취약점을 주장하려면 권한이 없는 주체가 어떤 경로로 정책을 깨는지까지 보여줘야 한다.

다음에 잠금 비트가 있는 설계를 읽는다면 아래 세 가지부터 남겨둘 생각이다.

- **설정:** 어떤 주체가 어떤 조건에서 잠금을 걸 수 있는가.
- **해제:** 정상적인 해제 경로와 허용되는 권한은 무엇인가.
- **초기화:** 리셋 종류별로 잠금과 보호 대상의 상태가 어떻게 달라지는가.

## 다음 기록에 남길 것

이번 예시에서 확인한 것은 정상 입력의 상태 유지와 금지 입력 뒤의 불확실성을 구분하는 방법이다. 실제 회로의 타이밍은 확인하지 않았다.

다음 실험에서는 D 래치로 범위를 좁혀, Enable이 열린 동안과 닫힌 동안을 비교해볼 만하다. 파형을 남기게 된다면 입력·출력 값에 더해 초기화 조건과 관찰 시점도 함께 적어두려고 한다. 값 하나보다 그 값에 도달한 과정을 남기는 편이, 나중에 기록을 다시 읽을 때 도움이 되겠다.
